Overview

I implemented a full custom CMOS circuit for F = AB + BC in Cadence Virtuoso, covering schematic capture, physical layout, DRC/LVS verification, and post-layout simulation with Calibre.

The circuit targets the GlobalFoundries PDK. I used a 2:1 PMOS:NMOS ratio to compensate for mobility differences and hit balanced rise/fall times. Final layout area: 12.748 µm².

Function Analysis & Optimization

Boolean Simplification

K-map analysis revealed a common factor, which cut the transistor count:

F = AB + BC = B(A + C)

This form enables direct complementary CMOS implementation with 8 transistors total (including the output inverter).

Network Design

Pull-Up Network (PUN):
  • 1 pMOS (B) in parallel with
  • 2 series pMOS (A and C)
  • Total: 3 pMOS transistors
Pull-Down Network (PDN):
  • 1 nMOS (B) in series with
  • 2 parallel nMOS (A and C)
  • Total: 3 nMOS transistors

Transistor Sizing

2:1 PMOS:NMOS ratio to account for lower hole mobility and keep rise/fall times balanced.

Layout Design

Strategy

  • pMOS transistors arranged for maximum diffusion sharing between adjacent devices
  • nMOS transistors placed to optimize diffusion continuity
  • Vias for cross-layer connections (C's drain to A's drain)
  • Metal1: horizontal tracks for VDD (top) and GND (bottom)
  • Polysilicon: vertical gate connections, minimal bends

Analysis

Post-layout delays go up because of parasitic junction capacitances, metal resistance, contact/via resistance, and gate-to-diffusion coupling. Going from 0.5 to 15 fF (30× increase) only produced ~8× longer delays, which lines up with how RC time constants scale.

Takeaways

  • Boolean simplification first - the factored form saved two transistors over sum-of-products
  • Parasitics hit harder than expected; +38-41% timing degradation even at minimum load
  • Source/drain sharing is worth the extra layout effort - got 25% area reduction
  • DRC/LVS debugging takes real time; 12 violations on the first pass alone
  • 2:1 PMOS:NMOS worked well for balancing rise/fall times here

Engineering Notes

Technical Reference

Function Form Selection

I went with F = B(A + C) over F = AB + BC to keep the series transistor stack shorter. The factored form only needs one series connection in the PDN (B gating the parallel A/C), while sum-of-products would require two separate series paths.

Sizing Strategy

Used 2:1 PMOS:NMOS based on the typical hole/electron mobility ratio in GF process. You could push to 2.5:1 for better balance, but the area hit wasn't worth it here.

PMOS Width
480 nm (8× minimum)
NMOS Width
240 nm (4× minimum)
Gate Length
60 nm (minimum feature size)

Inverter Placement

Output inverter uses the same sizing as the main stage. For a real design you'd size it based on actual fanout and load, but minimum sizing was fine here.

Diffusion Sharing

Adjacent transistors share source/drain diffusions where possible, reducing total active area by approximately 25% compared to isolated devices.

  • PMOS A and B share drain diffusion
  • PMOS B and C share source diffusion
  • NMOS devices share common source to GND

Metal Routing

Single Metal1 layer for all interconnects. VDD and GND rails run horizontally along the top and bottom edges. Signal routing uses vertical poly where possible to avoid extra metal crossings.

The via connecting C's drain to A's drain was a late fix after LVS flagged a mismatch. Adding explicit net labels in Virtuoso is non-negotiable.

Guard Ring

No guard ring in this design. A real cell would include substrate and well ties for latch-up protection.

LVS Debugging

First LVS run failed because of missing label attachments. Virtuoso needs explicit net labels on layout pins. Schematic net names don't carry over automatically.

  • Always verify pin labels after layout completion
  • Use Calibre's "discrepancy" view to trace net mismatches
  • Check that label layer matches PDK specification

DRC Iteration

First pass had 12 DRC violations, mostly metal spacing errors where signals converged near the output node. Fixed by widening the routing channel and jogging traces instead of going diagonal.

Simulation Setup

Ran post-layout sim against the schematic view by accident the first time and got suspiciously fast numbers. Need to set the config view to av_extracted in ADE before running.

Set config view to av_extracted before post-layout sims. Easy to miss, and the timing numbers look fine until you compare.
